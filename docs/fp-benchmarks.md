# Floating-point benchmark

Generated by `make fp-bench` (tools/fpbench.py).  Every run is in lockstep with the golden model.
Host: arm64, Darwin 27.0.0; simulator: Verilator.
The numbers are simulated cycle counts read from the core's own counters, so host load does not change them.

`sw/bench/fpbench` built three ways: **soft** = RV32IM with compiler-rt's soft-float routines, on core B; **hard** = RV32IMFD on core B with the FPU, `-ffp-contract=off`; **hard-fma** = the same with `-ffp-contract=fast` (a*b+c becomes one fused multiply-add).  Memory latency 10 cycles, default caches.

| Kernel | soft cycles | soft CPI | hard cycles | hard CPI | speed-up | hard-fma cycles | speed-up |
|---|---:|---:|---:|---:|---:|---:|---:|
| nbody | 3,789,153 | 1.31 | 126,950 | 4.81 | 29.8x | 106,694 | 35.5x |
| lu | 1,502,339 | 1.67 | 87,627 | 2.49 | 17.1x | 69,357 | 21.7x |
| poly | 1,263,836 | 1.07 | 54,159 | 3.65 | 23.3x | 32,044 | 39.4x |
| mandel | 4,865,792 | 1.14 | 212,639 | 3.33 | 22.9x | 188,030 | 25.9x |
| fir | 2,183,820 | 1.11 | 224,946 | 2.25 | 9.7x | 158,582 | 13.8x |
| total | 13,624,530 | 1.22 | 723,846 | 2.93 | 18.8x | 572,029 | 23.8x |

Kernels:

- `nbody`: 8 bodies, 12 leapfrog steps (mul, add, div, sqrt)
- `lu`: 20 x 20 LU factorisation with pivoting, and solve
- `poly`: degree-12 polynomial by Horner's rule, 400 points
- `mandel`: Mandelbrot escape counts, 24 x 12 points
- `fir`: 32-tap FIR filter, 400 samples, single precision
- `total`: all five

Result checksums (bit patterns), identical for soft and hard: nbody 24d0e6a25cb58ef1, lu 725fce16e534ae17, poly 99b8eda10c6895da, mandel e1f3ef9d38795ce4, fir 6cc68f47b6202f29, ops 37f988ad9e5de7f5.
hard-fma rounds each a*b+c once instead of twice, so its results differ in the last bits: nbody 24eae68a5cb58ef1, lu 35ff962ee928b61b, poly 8bb2227e07e4bfdb, mandel 7315865c46830ffc, fir 427c688ba6464376, ops 37c641966440b1f2.

## Cost of one operation

One operation per element of a 64-entry array of doubles, 8 passes: cycles per element, minus the cycles of a loop that only copies (so what remains is the operation plus the extra operand load).

| Operation | soft: cycles per element | hard: cycles per element | ratio |
|---|---:|---:|---:|
| a + b | 174.9 | 7.5 | 23x |
| a * b | 92.9 | 7.5 | 12x |
| a / b | 179.4 | 34.5 | 5x |
| square root | 2,020.2 | 32.5 | 62x |
| a < b | 30.7 | 3.8 | 8x |
| int to double | 17.4 | 4.5 | 4x |
| double to int | 23.9 | 1.6 | 15x |

(The copy loop itself: 7.2 cycles per element soft, 8.1 hard, where each 8-byte load or store is two word accesses.  The soft square root is the benchmark's own digit-by-digit routine, since compiler-rt has none.)

## FPU latency
